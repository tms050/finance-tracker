# Сценарии использования

## UC-01. Загрузка файла-выписки в .PDF

| Раздел | Описание |
| --- | --- |
| ID | UC-01 |
| Название | Загрузка файла-выписки в .PDF |
| Основной актор | Пользователь |
| Заинтересованные стороны | Пользователь |
| Цель | Импорт и сохранение данных о транзакциях из приложения банка |
| Предусловия | Программа запущена; у пользователя есть файл-выписка в формате .pdf |
| Постусловия (успех) | Транзакции из выписки сохранены в БД и доступны для просмотра |
| Минимальные гарантии | При сбое данные не сохраняются в БД; пользователь получает понятное сообщение об ошибке |
| Триггер | Пользователь нажимает кнопку «Загрузить файл» |
| Основной поток | 1. Пользователь выбирает файл-выписку через диалог выбора файла.<br>2. Система проверяет допустимость файла.<br>3. Система проверяет, не была ли эта выписка загружена ранее.<br>4. Система извлекает из выписки данные о счёте и транзакциях.<br>5. Система проверяет корректность и полноту извлечённых данных.<br>6. Система проверяет транзакции на дубликаты.<br>7. Система сохраняет новые транзакции в БД.<br>8. Система показывает отчёт о результате. |
| Альтернативные потоки | 2a. Файл не в формате .pdf -> сообщение об ошибке, поток завершается.<br>3a. Выписка уже загружалась ранее -> предупреждение. Пользователь выбирает: отмена / дополнить / перезаписать.<br>4a. Не удалось определить счёт -> система предлагает пользователю дополнить данные вручную, поток продолжается с шага 5.<br>5a. Часть данных не соответствует ожидаемой структуре -> сообщение с описанием проблем, сохранение не выполняется.<br>6a. Найдены дубликаты транзакций -> система показывает их список; пользователь по каждой решает: сохранить или пропустить. |
| Связанные UC | - |
| Частота | Регулярно, при появлении новых транзакций в банковском приложении |

## UC-02. Просмотр списка транзакций

| Раздел | Описание |
| --- | --- |
| ID | UC-02 |
| Название | Просмотр списка транзакций |
| Основной актор | Пользователь |
| Заинтересованные стороны | Пользователь |
| Цель | Просмотреть загруженные транзакции |
| Предусловия | Программа запущена; в БД есть хотя бы одна транзакция |
| Постусловия (успех) | Список транзакций отображён на экране |
| Минимальные гарантии | — |
| Триггер | Пользователь открывает раздел «Транзакции» |
| Основной поток | 1. Пользователь открывает раздел «Транзакции».<br>2. Система загружает транзакции из БД.<br>3. Система отображает список с возможностью сортировки и постраничной навигации. |
| Альтернативные потоки | 1a. В БД нет транзакций -> система показывает сообщение об отсутствии данных. |
| Связанные UC | extend: UC-04 (отметить перевод) - вызывается из списка |
| Частота | Регулярно |

| Заинтересованные стороны | Пользователь |
| Цель | Оценить доходы и расходы за выбранный период |

| Постусловия (успех) | Статистика отображена |

Система рассчитывает суммы доходов, суммы расходов и количество транзакций, исключая переводы себе на другой счёт.<br>4. Система отображает статистику. |

| Частота | Регулярно |

## UC-04. Отметка транзакции как "перевод самому себе"

| Раздел | Описание |
| --- | --- |
| ID | UC-04 |
| Название | Отметка транзакции как "перевод самому себе" |
| Основной актор | Пользователь |
| Заинтересованные стороны | Пользователь |
| Цель | Исключить переводы между собственными счетами из учёта доходов и расходов |
| Предусловия | В БД есть хотя бы одна транзакция |
| Постусловия (успех) | У выбранных транзакций установлен/снят признак «перевод самому себе» |
| Минимальные гарантии | При сбое изменения не сохраняются |
| Триггер | Пользователь ставит/снимает отметку «перевод» у одной или нескольких транзакций |
| Основной поток | 1. Пользователь выбирает одну или несколько транзакций.<br>2. Пользователь устанавливает отметку «перевод самому себе».<br>3. Система сохраняет изменения. |
| Альтернативные потоки | 2a. Пользователь снимает отметку -> система убирает признак; категория транзакции не меняется. |
| Связанные UC | extend: расширяет UC-02 |
| Частота | По мере необходимости |

## UC-05. Изменить категорию транзакции

| Раздел | Описание |
| --- | --- |
| ID | UC-05 |
| Название | Изменить категорию транзакции |
| Основной актор | Пользователь |
| Заинтересованные стороны | Пользователь |
| Цель | Уточнить принадлежность транзакции к категории для корректной статистики |
| Предусловия | Программа запущена; в БД есть хотя бы одна транзакция и хотя бы одна категория |
| Постусловия (успех) | Категория транзакции обновлена и сохранена |
| Минимальные гарантии | При сбое изменения не сохраняются, транзакция остаётся с прежней категорией |
| Триггер | Пользователь изменяет категорию у транзакции |
| Основной поток | 1. Пользователь выбирает транзакцию.<br>2. Пользователь выбирает новую категорию из справочника.<br>3. Система сохраняет изменение. |
| Альтернативные потоки | 2a. Справочник категорий пуст -> система предлагает сначала создать категорию (переход к UC-06).<br>2b. Пользователь отменяет изменение -> данные не меняются. |
| Связанные UC | extend: расширяет UC-02 |
| Частота | По мере необходимости |

## UC-06. Управлять категориями

| Раздел | Описание |
| --- | --- |
| ID | UC-06 |
| Название | Управлять категориями |
| Основной актор | Пользователь |
| Заинтересованные стороны | Пользователь |
| Цель | Вести собственный справочник категорий для классификации транзакций |
| Предусловия | Программа запущена |
| Постусловия (успех) | Справочник категорий создан/изменён/удалён согласно действию пользователя |
| Минимальные гарантии | При сбое справочник остаётся в прежнем состоянии |
| Триггер | Пользователь открывает раздел «Категории» |
| Основной поток | 1. Пользователь открывает раздел «Категории».<br>2. Система отображает текущий справочник.<br>3. Пользователь выполняет одно из действий: создать, изменить или удалить категорию.<br>4. Система сохраняет изменение. |
| Альтернативные потоки | 3a. Создание категории:<br>- пользователь вводит название, тип, при необходимости родителя;<br>- система проверяет уникальность в рамках родителя;<br>- при дублировании показывает сообщение, сохранение не выполняется.<br>3b. Изменение категории:<br>- пользователь меняет название, тип или родителя;<br>- система проверяет уникальность;<br>- при дублировании показывает сообщение, сохранение не выполняется.<br>3c. Удаление категории:<br>- если категория используется транзакциями, система предлагает подтверждение;<br>- после подтверждения категория удаляется, у связанных транзакций категория становится пустой. |
| Связанные UC | - |
| Частота | Нерегулярно, по мере настройки справочника |
